# 面试官情绪状态（Interviewer Mood）实施方案

## Context

当前面试官的"语气"是**静态**的：难度档 A/B/C 在 `build_profile()` 时一次性编译进配置，整场不变（见 [knowledge.py](file:///e:/shuangxingxi/AIagent/knowledge.py#L50-L66) 的 `LEVEL_STYLE`）。场内唯一的波动是 [voice.py](file:///e:/shuangxingxi/AIagent/voice.py#L43-L46) 那 ±3% 的去机械感抖动。

这带来一个真实的能力缺口：候选人练到的永远是"理性、耐心、客观的完美面试官"，遇到真实面试中的冷脸/赶时间/反复质疑时容易崩。

本方案把**情绪**做成一个独立于**难度**的维度，并让它在对话中动态演化；面试结束后揭示状态轨迹并给出归因，训练用户区分"是我的问题"还是"对方的问题"。

**目标产出**：面试官有可变的情绪状态 → 影响措辞、节奏、语速 → 面试后给出双分数与归因复盘。

---

## 一、先解决两个设计冲突

### 冲突 1：情绪与难度语义重叠

现在 A 档的 `probe_style` 是「连续深挖，对结论主动提出质疑（**压力面**）」——"压力面"本身是一种情绪，和新增的"压力型模式"重复。如果直接叠加，会出现 A 档 + 压力型 = 双重攻击。

**解法：重新划分职责，两轴正交**

| 轴 | 决定什么 | 取值 |
|---|---|---|
| 难度（已有） | 考察内容的深度、考点层级、评分严格度 | A / B / C |
| 情绪（新增） | 态度、耐心、反馈风格、追问犀利度、语速语气 | 6 种模式 |

具体改动：把 `LEVEL_STYLE` 里属于"态度"的措辞从 `probe_style` 中摘出去，只保留"强度"。例如 A 档改为「连续深挖，直到答到原理层」，把"主动质疑"移交情绪维度。

分离后所有交叉组合都成立且真实：A 档 + 友善 = 资深温和的面试官；C 档 + 冷淡 = 题不难但态度差（不专业的面试官，正好是训练素材）。

### 冲突 2：「打断」在现有技术栈上不可实现

`st.chat_input` 与 `st.audio_input` 都是阻塞式——候选人提交前 Agent 拿不到任何输入；语音模式更是整段 WAV 一次性上传，没有流式。

**解法：不实现真打断，改为「抢话感」**

提示词层明确：当耐心低或时间压力高时，**跳过一切客套与过渡，第一句直接承接追问**，且不超过 8 个字。心理效果接近被打断，且不撒谎。作品文档里如实写"抢话感"而非"打断"。

## 二、新增模块 mood.py

独立成文件，与现有 `resume.py` / `voice.py` 的单一职责风格一致。

### 状态变量（3 个内部量 + 1 个派生量）

| 变量 | 范围 | 含义 |
|---|---|---|
| `patience` | 0–3 | 耐心，影响追问耐心与反馈意愿 |
| `energy` | 0–2 | 精力，影响回复长度与投入感 |
| `pressure` | 0–2 | 时间压力，由实际耗时推导 |
| `mood` | 派生 | 由 patience × energy 二维派生的对外表现标签 |

`mood` 派生表（可解释、无歧义）：

| | energy 高 | energy 低 |
|---|---|---|
| **patience 高** | 投入 | 例行公事 |
| **patience 低** | 急躁 | 冷淡 |

### 纯函数式状态机

```python
def update(state: dict, *, answer: str, decision: dict, elapsed_min: float,
           planned_rounds: int, cur_q: int) -> dict
```

**必须是纯函数**（无随机、无全局状态），这样可离线单测且可复现。规则示例：

- 上轮 `action == "probe"` 且 `gap` ∈ {缺量化结果, 缺技术原理} → `patience -1`
- 回答含量化信号（正则 `\d+%|\d+ms|\d+倍|QPS|P99|\d+万`） → `patience +1`、`energy +1`
- 回答长度 > 120 字且含因果连接词（因为/所以/原因是） → `energy +1`
- 连续 2 轮 `action == "ask"` → `patience +1`
- `elapsed_min > planned_rounds * 4` 或 `cur_q >= planned_rounds` → `pressure +1`

所有量 clamp 到各自上界。

## 三、六种情绪模式（knowledge.py）

新增 `MOOD_MODES` 表，每种模式定义：初始状态、提示词风格串、语音偏移基线。

| 模式 | 表现 | 训练目的 |
|---|---|---|
| 随机（默认） | 每场从下列模式随机抽一个，且不告知 | 逼近真实不确定性 |
| 友善型 | 鼓励、引导、给正向反馈 | 对照组，正常发挥 |
| 疲惫型 | 语速快、回复短、少反馈、急于推进 | 抗压、简洁表达 |
| 怀疑型 | 反复质疑结论、索要证据 | 论证能力、心态稳定 |
| 冷淡型 | 极少回应、不引导、不评价 | 自我驱动、不依赖反馈 |
| 压力型 | 主动挑刺、抢话、压缩思考时间 | 高压面试 |

模式随 `build_profile(..., mood=...)` 一起编译进配置，**沿用现有 `strict` / `max_probes` / `allow_reflect` 的编译模式**，不新增分支代码。

### 与「严格模式」的交互规则

`strict=True` 的目的是"每场节奏一致"，与情绪漂移矛盾。规则：**严格模式下锁定为友善型，不随机、不漂移**。

### 硬性安全约束（写进提示词）

压力/冷淡模式**只允许质疑答案，禁止贬低候选人本人**。禁止出现人格评价、嘲讽、贬低学历/背景的表述。这是提示词层的硬红线。

## 四、三个输出通道

### 通道 1：措辞（agents.py 提示词注入）

`_build_interviewer_system()` 新增 `mood_state` 参数，注入一段【当前状态】：

- 状态标签 + 具体行为指令（如 patience 低 → 不给正向反馈、追问不容缓冲）
- 抢话规则（见冲突 2 的解法）
- 禁用话术清单（针对压力型）

### 通道 2：节奏（mood 调制 max_probes）

不耐烦时更快放弃当前题，友善时愿意多给机会：

```
effective_max_probes = clamp(base_max_probes + patience - 1, 1, 4)
```

`_apply_fallbacks()` 里的上限从常量改为这个动态值。**兜底仍然由代码持有**，不交给模型。

### 通道 3：语音（voice.py）

`_tone_args(level, mood)` 改为双查表：难度档给基线，mood 叠加偏移（如"急躁"`+6% / -3Hz`，"例行公事"`-4% / +1Hz`）。保留现有 ±3% 随机抖动。

## 五、归因报告（本方案的核心价值）

**这一层不做，整个特性不该上线**——否则会出现"面试官被设定成挑刺 → 用户被逼到语无伦次 → 评估官照常打低分 → 用户确认自己确实很差"，这是负向强化，比不做更糟。

### 5.1 状态轨迹记录（app.py）

`advance()` 每轮把 `(主问题, 动作, patience, energy, pressure, mood)` 追加到 `st.session_state.mood_trace`，随 `decisions` 一起落盘到 `history.json`。

### 5.2 评估官输出双分数（agents.py）

`evaluate_interview()` 新增 `mood_trace` 参数，`EVALUATOR_SYSTEM` 增加归因要求与字段：

- `overall_score` — 原始表现分（**保持现有语义**，不破坏历史记录兼容）
- `adjusted_score` — 剥离对方状态干扰后的真实水平估计
- `attribution` — 归因说明：哪些扣分来自面试官状态，哪些来自候选人自身

### 5.3 教练新增抗压维度

`COACH_SYSTEM` 增加 `resilience` 字段：候选人在低耐心/高压力下的表现（是否慌乱、是否过度道歉、是否逻辑崩塌），并给出针对性练习动作。教练同样需要拿到 `mood_trace`。

### 5.4 报告 UI（app.py）

「评分报告」页顶部新增归因区块：并排展示两个分数 + 状态轨迹（复用现有 `st.dataframe` 与 `st.bar_chart` 写法）+ 一句明确结论。

### 5.5 伦理边界的落地

**选定：开始前弹确认框（知情同意）+ 允许随时结束、不支持中途切换。**

- 选中**高强度的疲惫/怀疑/冷淡/压力型**时，侧边栏出现确认勾选框「我了解这是为训练目的设计的模拟状态，不是对真实面试官的平均描述」，**未勾选时「开始面试」按钮保持 disabled**。友善型与随机型不需要确认
- 退出走现有的「结束面试并生成报告」按钮，在高强度模式下标明"可随时结束"
- **不提供中途切换情绪模式**：切换会让状态轨迹出现断点，评估官的归因分析失去依据。模式在 `start_interview()` 时锁定，整场不变
- 报告页显著位置标明："本场面试官的部分表现是为训练目的设计的状态模拟，不代表真实面试的普遍情况。若遇到此类面试官，问题在对方，不在你。"
- 幻灯片/文档里不把"被羞辱"包装成正常职场

## 七、实施顺序

按"可提交性"排序，每一阶段结束都是可演示状态：

1. **阶段一 · 会变化的面试官**：`mood.py` + `MOOD_MODES` + 侧边栏选择 + 提示词注入 + 轨迹记录
2. **阶段二 · 归因闭环**：评估官双分数 + 教练 `resilience` + 报告 UI（差异化核心）
3. **阶段三 · 语音联动**：`voice.py` 双查表

时间紧张时，阶段一 + 二是最小可提交单元；阶段三可割舍。

## 八、验证方案

**离线（可复现）**

- `mood.py` 状态机单测：构造确定的 `(answer, decision)` 序列 → 断言 `patience` / `energy` / `pressure` 轨迹与 `mood` 派生标签，纯函数保证结果稳定
- 边界：clamp 上界、连续 probe 打到底、单轮内多规则同时命中
- 正则量化信号识别：正例（`P99 降到 120ms`）与反例（`大概几百`）分别断言

**在线（真实调用）**

- 同一份回答脚本，分别用「友善型」与「压力型」各跑一场，对比：措辞差异、追击强度、评估官输出的 `adjusted_score` 差值是否合理（压力场不应显著拉低校正分）
- 跑一场 6 轮完整面试，确认报告页双分数与状态轨迹正确渲染

**回归**

- `AppTest` 跑界面：新增下拉存在、无异常、报告页新字段渲染
- 既有兜底用例（开场强制 ask / 问满强制 end / 追问超限 / reflect 连用超限）全部复测，确认动态 `max_probes` 未破坏它们
- `DESIGN.docx` 导出后校验段落与表格数、关键字段存在

## 九、已知风险

| 风险 | 应对 |
|---|---|
| 提示词变长，DeepSeek 返回空 JSON 的概率上升 | 复用现有 `chat_json` 重试机制（3 次 + 降温度）；注入段落控制在 150 字内 |
| 动态 `max_probes` 破坏既有节奏可预期性 | 严格模式锁定友善型且固定上限；兜底仍在代码侧 |
| 压力模式输出越界（人身攻击） | 提示词硬红线 + 在线抽查多个模式的产出 |
| 双分数让模型困惑 | 单轮新增字段已验证安全（`gap` 字段先例），并在提示词中给出取值关系说明 |
