# 知遇 · 多场景多难度自适应 AI 虚拟面试智能体

面向**考研复试 / 应届校招 / 日常实习 / 转正就职**四类考生的模拟面试 Agent。
不是题库，而是一套**会现场追问**的面试官引擎：同一套代码，靠「场景 × 专业 × 难度」
三级配置，还原不同面试官的真实差异，并在面试后给出**可执行**的复盘报告。

## 快速开始

```powershell
py -3.12 -m pip install -r requirements.txt
$env:DEEPSEEK_API_KEY = "sk-xxxx"        # 必需：面试官 / 评估官 / 教练 / 建议官 / 简历优化官
$env:SILICONFLOW_API_KEY = "sk-xxxx"     # 可选：语音识别与合成兜底
py -3.12 -m streamlit run app.py
```

浏览器打开后，在左侧选「场景 → 专业 → 难度」，可选填候选人背景或上传简历，
点「开始面试」即可。API Key 也可以直接在侧边栏手填，不必设环境变量。

侧边栏另有一组**「📝 简历优化（独立功能）」**：上传简历即可拿到**诊断 + 逐条改写对照**，
**不需要先开一场面试**。它的卖点是"不替你编简历"——模型给出的每条改写，
本地都会核对原句是否真在简历里、改写有没有补上原文没有的数字，对不上的一律剔除。

面试结束后，还可以在报告页或历史页给这场**回填真实结局**（进入下一轮 / 拿到 offer /
被拒 / 还没结果）。回填几场之后，历史页会告诉你：**分数和结局对得上吗、偏乐观还是偏保守、
哪个难度档看不清**。校准**只做对照、不反调分**——同一份回答在任何时候都得到同一个分数。
样本不足时它会直接说"还不够下结论"，不会硬给一个百分比。

## 评分校准（v16）

面试评分本质是一次**预测**，候选人真实的「进 / 挂」才是标签。有了标签才能回答
"我的分数准不准"。三条设计红线：

1. **不反调分**。`calibration.py` 是**只读纯函数**：不写回 `history.json`、
   不影响任何一场的分数。口径若随样本漂移，同一份回答在不同时间会得到不同分数，
   与"可控可解释"直接冲突。
2. **灰区不入分母**。分数落在 55~75 之间时，评分本身没给明确判断，
   这类场次计入"样本"但不算进准确率的分母。
3. **样本不足就直说**。可判定场次 < 3 时指标卡显示「—」并注明"样本不足"，
   绝不在旁边写着"样本还太少"的同时打一个 100%。

## 隐私说明

- **简历**：只在当前会话内存中处理，**从不写入磁盘**，面试结束即清除。
  「简历优化」功能同理：结果也只留在页面上，只有你主动点「导出优化建议」时才落成文件。
- **提升建议**：按评分维度给出的建议**不写入 `history.json`**——它每条都引用你的原话，
  属于个人化内容。它只出现在本场报告页，以及你主动导出报告时的 Markdown 里。
- **面试逐字稿**：会落盘到 `history.json`（供回看与跨场对比）。该文件已加入
  `.gitignore`，因为其中可能含真实候选人的个人信息。界面提供**逐场删除**与
  **清空全部**（两步确认）两个入口。
- **API Key**：一律从环境变量或界面读取，**不写入任何文件**。

## 数据覆盖范围（如实声明）

项目里有**两层**知识数据，覆盖范围不同，务必区分：

### ① 考点参照库 `rubrics.json` —— 6 个专业全覆盖

| 专业 | 能力维度 | 考点（A / B / C） | 参照条目 |
|---|---|---|---|
| 计算机科学与技术 | 5 | 18 / 24 / 18 | 60 |
| 人工智能 | 5 | 20 / 15 / 17 | 52 |
| 软件工程 | 5 | 15 / 15 / 17 | 47 |
| 电子信息 | 5 | 15 / 15 / 17 | 47 |
| 自动化 | 5 | 15 / 15 / 17 | 47 |
| 通信工程 | 5 | 15 / 15 / 17 | 47 |
| **合计** | **30** | **98 / 99 / 103** | **300** |

外加**行为面**一套独立的 STAR 五维（情境/行动/结果/反思/表达），不绑定专业。
因此 **6 个专业都能正常面试、正常评分**。

### ② 真实企业真题 + 自建真题 —— 6 个专业全覆盖

| 池 | 条数 | 来源 |
|---|---|---|
| 技术面 · 软件工程 | 800 | 外部开源题库 |
| 技术面 · 计算机科学与技术 | 244 | 外部开源题库 |
| 技术面 · **人工智能** | **52** | **自建**（由 300 参照反向改写）|
| 技术面 · **电子信息** | **47** | **自建** |
| 技术面 · **自动化** | **47** | **自建** |
| 技术面 · **通信工程** | **47** | **自建** |
| 行为面（6 专业通用） | 56 | 外部开源题库 |
| 陷阱追问（6 专业 46~60） | 299 | **自建** |

**补位规则**：外部真题优先；外部池为空时自动改用自建真题。
两种来源在提示词里**措辞不同**——自建题明确标注「按评分参照改写」，
并禁止面试官向候选人声称"来自某家真实企业"，避免编造出处。

**为什么自建而不是抓外部题库**：检索到的候选仓库有三个硬障碍——
① 几乎全部无许可证；② 性质是期末考试资料而非面试题；
③ 口径是本科课程而非岗位面试。与其硬凑，不如用自己的 300 条参照反向改写：
质量可控、零许可风险，且与评分口径**天然同源**。

**陷阱追问的设计**：由每条参照的 `common_errors` 反转而来，供面试官在追问阶段
主动设伏（如"有候选人说『能控性矩阵满秩要求矩阵为方阵』，你同意吗？"）。
它**不混入主问题池**——否则等于把正确答案或误区直接抛给候选人。
生成时会截掉「实际上……」之后的内容，防止泄露答案。

**未覆盖的专业大类**：经管（会计/金融/工商管理）、文科（法学/新闻/汉语言）、
理科（数学/物理/化学）、其他工科（机械/土木/材料/环境）、设计艺术。
当前 6 个专业全部属于「计算机 + 电子电气」这一簇，是刻意收敛的结果
（`build_profile` 用精确查表，专业名必须命中 `MAJORS`）。扩展新专业需
同时补「5 维度 × 3 档 × 15 考点起」与对应的 45~60 条参照。
